# 桌面端意见反馈

入口位于导航栏右侧「反馈」，不改变原有三个页面，也不依赖游戏客户端是否在线。

## 表单

- 必填：问题类型（功能异常 / 改进建议 / 其他问题）、描述（去除首尾空白后 10–5000 字符）。
- 选填：联系方式（最多 200 字符）、截图（最多 3 张；PNG/JPEG/WebP，每张不超过 5 MiB）。
- 自动附带：应用专属设备 ID、软件版本、系统版本及架构。提交前可展开查看，必须勾选同意发送。
- 仅发送用户主动选择的图片；不自动截屏、不附带日志、账号、LCU 凭据、进程列表或原始设备标识。
- 草稿仅保留于本次进程内存，关闭弹窗不丢失，成功后清空，退出应用后不保存。

## 设备 ID

按需在首次打开反馈时读取 Windows MachineGuid（64 位注册表视图）；macOS 使用 IOPlatformUUID，Linux 使用 machine-id。
主进程对「固定应用命名空间 + 平台 + 系统标识」计算 SHA-256，仅发送小写 64 位十六进制哈希。
读取过程使用固定命令参数，不启动可见控制台，无轮询、不访问网络；原始值不记录或传出主进程。

哈希保存到 `app.getPath('appData')/lol-viewer-identity/device-id`，独立于安装目录和战绩缓存。
一般卸载重装软件、升级、清理战绩缓存不会改变它；标识文件丢失时可依据相同系统标识重新得到同一 ID。
系统标识不可读取时，使用随机 UUID 的应用专属哈希并持久化，此时若同时清除标识文件，不能保证重装后相同。
重装系统、克隆系统或更换硬件可能导致改变或重复；它不是全球唯一硬件身份，不能作为授权或认证凭据。
保留的哈希优先，避免系统标识临时不可用时变更。该标识仍属于可关联设备的假名标识，不宣称匿名化。

## 接口契约与上线前提

生产地址固定为 `https://19950919.me/lol-admin/api/feedback`，保留域名根目录已有的授权服务。
后台须先实现并部署以下扩展后，客户端才能端到端使用；不能直接对接旧版仅接收 JSON 的反馈接口。

`POST multipart/form-data`：

| 字段 | 来源 |
| --- | --- |
| type | BUG / SUGGESTION / OTHER |
| description、contact | 用户输入 |
| deviceId、clientVersion、systemInfo | 主进程产生，渲染端不能覆盖 |
| requestId | 每份草稿的 UUID；修改内容后换新，失败重试保持相同 |
| screenshots | 可选、重复文件字段；不传本地路径或原始文件名 |

主进程校验白名单字段、图片格式签名、base64 编码与体积后发起请求。文件名统一为 `screenshot-N.png/jpg/webp`。
后台仍须独立校验并安全解码、限制像素、去除元数据，只允许管理员查看图片；不能信任客户端校验。
禁止重定向上传；30 秒超时；响应体上限 16 KiB；不自动重试、不打印反馈或网络异常细节。

只有 201 或幂等重放的 200，以及合法 `{ "id": "FB-<20位大写十六进制>" }` 才提示成功。
后台应对同 deviceId + requestId + 内容的重试返回同一编号，冲突返回 409；未完成幂等支持前不能宣称重试不重复入库。
429、413、网络失败、无效响应都显示明确提示并保留草稿。

## 开发与验证

非打包运行可通过 `LOL_VIEWER_FEEDBACK_URL=http://127.0.0.1:<port>/api/feedback` 指向本地接口；只允许 HTTP loopback 覆盖，打包后忽略覆盖值。
`--fixture-live-match` / `--fixture-aram` 使用假的设备 ID，默认阻止向线上提交；仅显式指定 loopback 测试接口时允许提交。
开发模式版本读取桌面包自身 package.json；正式安装包通过 app.getVersion() 读取，发布时需要配置实际版本号。

测试覆盖：设备 ID 重装重建/重启稳定、随机回退、IPC 来源和字段校验、请求封装、格式与图片限制、失败反馈，以及真实 Electron 表单→本地 HTTP 接口的截图上传与幂等请求 ID 重试。
Windows MachineGuid 读取和卸载重装仍需 Windows 实机验收；macOS 不代替该验收。

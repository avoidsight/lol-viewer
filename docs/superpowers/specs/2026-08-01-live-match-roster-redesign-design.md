# LOL Viewer 对战阵容页与首页刷新设计

## 目标

国服隐藏其他玩家历史数据时，对战页仍应稳定展示完整的双方阵容，不再用十张高大的空战绩卡占据页面。首页提供明确的手动刷新入口，便于重新获取个人战绩。

## 对战页信息架构

- 页面顶部显示“对战信息”、当前模式和数据状态。
- 主体采用上下两排布局：上方队伍 5 人，下方队伍 5 人。
- 能识别本地队伍时使用“己方 / 敌方”；无法识别时使用“队伍 1 / 队伍 2”，不猜测阵营。
- 位置可靠时按 TOP、JUNGLE、MIDDLE、BOTTOM、UTILITY 排序；大乱斗或位置未知时按客户端阵容顺序展示。
- 每张紧凑卡片常驻展示英雄头像、玩家名或隐私占位名、位置或阵容序号、召唤师技能和段位。
- 有近十场数据时展示场次、胜率、KDA 和最近对局摘要；没有数据时只显示小型“战绩受国服隐私保护”状态，不再保留空白战绩列表。
- 两排阵容保持列对齐，在窄窗口中整体横向滚动，不压缩英雄头像和文字至不可读。

## 首页刷新

- 在个人战绩页顶部资料概览右侧增加“刷新”按钮。
- 点击后重新调用个人战绩接口；刷新期间按钮禁用并显示“刷新中”。
- 首次加载仍使用原有加载状态。
- 已有数据刷新失败时保留旧数据，并在按钮附近显示“刷新失败，请重试”，避免整页退回不可用状态。
- 刷新成功后替换为新数据并清除错误提示。

## 组件与数据流

- `App` 继续负责个人战绩请求状态，并向 `PersonalHistoryPage` 传入刷新回调、刷新状态和提示。
- `PersonalHistoryPage` 只负责按钮和反馈展示，不直接调用 preload API。
- `LiveMatchPage` 负责两支队伍排序、阵营标签和总体布局。
- `PlayerCard` 根据 `PlayerSnapshot.status` 在“完整战绩摘要”和“紧凑隐私状态”之间切换。
- LCU 和 IPC 数据协议保持不变，本次只调整界面和刷新交互。

## 错误与隐私状态

- 阵容可读但历史不可读：展示阵容和隐私状态。
- 阵容仍在加载：显示固定尺寸骨架槽位，避免页面跳动。
- LCU 完全不可用：显示页面级错误和重试入口。
- 不将匿名玩家误标为己方，也不展示或记录原始敏感标识。

## 验证

- 组件测试覆盖完整战绩、十人均无战绩、部分玩家无战绩、阵营未知、位置未知和大乱斗顺序。
- `App` 测试覆盖首页手动刷新成功、刷新失败保留旧数据、刷新中防重复点击。
- 运行完整 Vitest、TypeScript 类型检查、Electron 生产构建和 SQLite 冒烟测试。
- 最终生成新的 Windows x64 便携版 ZIP。

# 自动接受匹配设计

## 目标

为桌面查看器增加可选的“自动接受匹配”功能。用户开启后，只要查看器保持运行，主进程检测到英雄联盟客户端进入 `ReadyCheck` 阶段，就自动调用 LCU 接受接口。功能默认关闭。

## 行为边界

- 仅调用 `POST /lol-matchmaking/v1/ready-check/accept`。
- 不自动开始匹配、不选英雄、不操作符文或召唤师技能。
- 开关关闭后立即停止检测与接受。
- 切换查看器页面不影响后台功能；退出查看器后功能停止。
- 同一次 Ready Check 最多提交一次；阶段离开 `ReadyCheck` 后重置去重状态。
- 客户端未启动、认证失效或接口暂时失败时静默等待下一轮，不影响其他页面。

## 数据与界面

在 `AppSettings` 增加 `autoAcceptReadyCheck: boolean`，默认值为 `false`，通过现有 SQLite 设置表持久化。数据库迁移为 `app_settings` 增加布尔列，并兼容已有用户数据库。

开关放在“对战信息”页现有设置区，标签为“自动接受匹配”。保存失败时沿用现有设置错误提示。

## 主进程结构

新增独立 `ReadyCheckAutoAcceptor`：

1. 每 1000 毫秒读取最新设置；关闭时不连接 LCU。
2. 开启时发现 LCU，并读取 `/lol-gameflow/v1/gameflow-phase`。
3. 第一次进入 `ReadyCheck` 时调用接受接口并标记本轮已处理。
4. 阶段离开 `ReadyCheck` 后清除标记，为下一次匹配做准备。
5. 应用退出时清理定时器，禁止未处理异步任务继续执行。

LCU HTTP 客户端增加固定路径的无正文 `POST` 能力；路径仍必须以单斜杠开头，目标仍固定为 `127.0.0.1`，令牌不得进入日志或渲染进程。

## 测试与验收

- 设置 schema、默认值、SQLite 迁移和持久化测试。
- HTTP POST 方法、认证、状态码和路径校验测试。
- 自动接受器覆盖：默认关闭、ReadyCheck 接受一次、重复轮询不重复、离开后可再次接受、关闭立即停止、dispose 清理。
- React 设置开关加载、切换与保存测试。
- 完整单元测试、类型检查、生产构建和 Electron 端到端测试。
- 真实国服验收只在用户实际进入匹配确认窗口时完成；没有发生 Ready Check 前不得宣称真实自动接受已经验证。

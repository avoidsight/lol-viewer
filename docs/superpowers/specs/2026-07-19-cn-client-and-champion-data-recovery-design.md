# 国服客户端与英雄资料可用性修复设计

## 背景

当前发布版在真实国服环境中存在两个发布阻断问题：查看器以普通权限运行时无法读取由 WeGame 高权限启动的 `LeagueClientUx.exe` 参数，因而把已启动的客户端误报为未启动；英雄资料库默认请求未随应用发布的 `127.0.0.1:8787` 服务，首次安装后必然无数据。此前以 fixture、模拟 LCU 和提权脚本完成的测试没有覆盖用户实际启动方式。

## 目标

- 在 WeGame 国服客户端的实际权限模型下稳定发现并认证 LCU。
- 战绩、对战信息在大厅、结算页、选人阶段和游戏中给出符合当前状态的结果，不把“当前无对局”误报为“客户端未启动”。
- 英雄资料库不依赖用户另行启动本地服务。
- 在线数据失败时仍能展示明确标注版本和更新时间的离线内容。
- 发布前必须使用最终构建产物按用户实际启动方式验收。

## 方案

### 1. 客户端权限与发现

Windows 发布程序声明需要管理员权限，启动时由系统显示 UAC。查看器与 WeGame/英雄联盟处于相同权限级别后，通过 `LeagueClientUx.exe` 的完整命令行读取 `--app-port` 和 `--remoting-auth-token`。解析器同时兼容 Riot 标准参数与腾讯客户端“完整参数带引号”的格式。

发现失败时区分并展示以下状态：客户端进程不存在、权限不足、参数格式不兼容、LCU 认证失败。界面不再把所有错误统一显示成“请先启动英雄联盟客户端”。日志不得记录令牌。

### 2. 页面状态语义

- 战绩页只依赖当前召唤师与历史战绩接口，不依赖当前对局。
- 对战信息页在大厅或结算页显示“当前没有进行中的对局”，在选人和游戏中加载十名玩家。
- ARAM 等无法可靠按位置配对的模式按客户端队伍顺序展示；召唤师峡谷默认按位置配对。

### 3. 英雄资料数据

移除生产环境对 `127.0.0.1:8787` 的隐式依赖。主进程使用可配置的 HTTPS 在线数据源获取按版本、英雄和位置划分的出装与优劣对位快照，并继续执行严格结构校验、五秒超时和 SQLite 缓存。

应用随包附带一份经过同一 schema 校验的离线快照。在线服务失败时优先使用当前版本缓存，其次使用最近缓存，最后使用随包离线快照，并在页面明确标注“离线数据”及数据版本。不得伪造实时胜率或把示例数据标为在线数据。

若在线来源暂时只能覆盖部分英雄，资料库必须展示覆盖范围，未覆盖英雄给出明确提示，而不是空白或通用“不可用”。

### 4. 安全与错误处理

- LCU 仅连接 `127.0.0.1`，认证令牌只保存在主进程内存中。
- 渲染进程不接触令牌，也不能传入任意 URL。
- 外部英雄数据必须为 HTTPS、固定允许的主机，并通过现有 Zod schema 校验。
- 面向用户的错误包含可操作建议；内部网络地址、令牌和堆栈不进入界面。

## 测试与验收

自动化测试采用红—绿流程覆盖：腾讯带引号参数、权限/发现错误分类、无当前对局状态、战绩页不依赖 gameflow session、在线英雄数据、缓存降级和随包离线降级。

最终验收必须使用最终构建产物完成：

1. WeGame 和国服客户端已启动、查看器从桌面正常启动并通过 UAC。
2. 大厅状态下战绩页能读取个人战绩，对战页显示“当前没有进行中的对局”。
3. 结算页仍能读取个人战绩。
4. 召唤师峡谷选人或游戏中展示双方十人并默认按位置对比。
5. ARAM 选人或游戏中展示双方十人且不错误声明位置可靠。
6. 断网后英雄资料库显示缓存或随包离线数据及明确标记。

只有上述与完整自动化测试、类型检查、生产构建均通过后，才生成新的安装包；旧安装包不得作为修复版交付。

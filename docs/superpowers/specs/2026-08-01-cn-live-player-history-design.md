# 国服实时对局十人战绩设计

## 目标

在对局信息页展示当前对局双方十名玩家。每名玩家只展示当前英雄、Riot ID、与当前队列匹配的段位，以及最近十场比赛的英雄、K/D/A、胜负和比赛类型。

## 数据规则

- 从游戏流程会话读取双方阵容、当前英雄和召唤师标识。
- 通过召唤师接口把 `summonerId` 解析为 Riot ID 和 PUUID。
- 最近战绩必须使用 PUUID 请求国服客户端的比赛历史接口；当前玩家接口仅作为降级路径。
- 当前对局为灵活排位时展示 `RANKED_FLEX_SR` 段位；其余队列展示 `RANKED_SOLO_5x5` 段位。对应段位不存在时显示“未定级”。
- 最近十场不按队列过滤，按结束时间倒序取十场。
- 每场仅保留英雄、K/D/A、胜负和可读的比赛类型。
- 单个玩家接口失败不得阻塞其余九名玩家；失败卡片显示明确的加载失败状态并允许后续轮询恢复。

## 头像资源

当前英雄和历史英雄头像优先从已连接的本地英雄联盟客户端静态资源读取，避免依赖 CommunityDragon 外网。客户端资源不可用时再使用打包内占位图，不显示数字方块。

## 页面结构

- 页面保持上下两排，每排五名玩家；上排为己方，下排为敌方。
- 玩家卡片顶部依次展示当前英雄头像、Riot ID、段位。
- 卡片主体使用紧凑的两列五行战绩列表，共十场。
- 每条战绩展示英雄小头像、胜/负、K/D/A、比赛类型，不增加伤害、承伤、金币、补刀等指标。
- 对局信息未就绪时每三秒刷新；数据出现后停止空状态轮询，单个失败玩家可独立重试。

## 数据流与缓存

1. 游戏流程会话产生十人基础阵容。
2. 身份解析层并发补全 Riot ID 与 PUUID。
3. 玩家数据层以 PUUID 并发获取段位和最近十场。
4. 适配层把国服响应转换为现有 `PlayerSnapshot`。
5. 缓存以 PUUID 为主键，避免 Riot ID 改名或 `summonerId` 用错导致缓存失配。
6. 渲染层逐个接收玩家快照并增量更新卡片。

## 错误处理

- 身份接口失败：保留阵容位置和英雄，ID 显示“读取失败”。
- 历史接口失败：显示“战绩加载失败”，不再误报为国服统一隐私保护。
- 段位接口失败：段位显示“读取失败”，战绩仍正常展示。
- 头像失败：使用统一英雄占位图。

## 验证

- 单元测试证明历史与段位接口使用 PUUID，而非 summonerId。
- 单元测试覆盖灵活排位和其他模式的段位选择规则。
- 单元测试覆盖十场战绩字段与排序。
- 单元测试覆盖一名玩家失败不影响其余玩家。
- 使用真实国服对局烟雾测试确认十个 Riot ID、当前英雄、对应段位和最近十场均能解析。
- 完成类型检查、全量测试、生产构建和便携包验证。
